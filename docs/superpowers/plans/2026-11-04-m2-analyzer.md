# Milestone 2: Audio Analyzer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn any song into the per-frame band, loudness, kick and hit data the visuals react to, cached per song, with one command (`npm run analyze -- <file>`) that milestone 3 uses to drive the Particle Horizon template.

**Architecture:** The Python analyzer is split in two. `analyzer/features.py` holds pure number-crunching functions that take NumPy arrays (easy to test with generated sounds). `analyzer/analyze.py` decodes a file with FFmpeg, runs the features, and writes `analysis.json`. On the TypeScript side, `src/lib/songs.ts` fingerprints a song (SHA-256), converts it to `song.wav`, runs the analyzer, and caches both in `storage/songs/<sha256>/`. `scripts/analyze.ts` is the developer command around it.

**Tech Stack:** Python 3.14 + NumPy 2 + pytest (venv at `analyzer/.venv`), FFmpeg 8, TypeScript (strict) + Vitest, tsx.

**Spec:** `docs/superpowers/specs/2026-11-04-music-visualizer-app-design.md`: §7 Audio analysis (the source of every number below), §10 error rows "Unsupported or corrupt audio file" and "Analyzer fails", §11 Testing (Analyzer), §13 milestone 2 ("passes its tests; analyzes T-REX in < 10 s").

## Global Constraints

- Analysis numbers, verbatim from spec §7: mono **44.1 kHz**; **30 fps**, one analysis frame per video frame; FFT window **4096 Hann**; **32** log bands **30 Hz–16 kHz** in dB; bands scaled against the whole song from the **20th–97th** percentile to 0–1; smoothing attack **0.55** / release **0.12**; hits at least **0.15 s** apart; kick decay **≈ 0.22 s**; values rounded to **3 decimals**.
- Output shape, verbatim: `{version, fps, bands, duration, frames:[{b:[…32], l, k, f}], hits:[[t, strength]…]}`. `version` starts at **1**; changing it invalidates every cached analysis.
- Prototype values the spec says to build from (`analyze.py` in the research notes) and that this plan keeps: loudness scaled from the **15th–98th** percentile and smoothed **0.5 / 0.1**; kick flux uses the lowest **8** bands; adaptive hit threshold = mean flux over **±0.5 s** × **1.4** + **0.12**.
- One deliberate addition to the prototype (verified on T-REX: mean band change 0.0004, same 410 hits): before percentile scaling, band dB values are floored at **(99.5th percentile of all band values) − 60 dB**, and each band's scale range is at least **12 dB**. Without it, near-silent bands and tone leakage get stretched to full brightness and the spec's tone tests fail.
- Cache layout: `storage/songs/<sha256 of the source file>/song.wav` (stereo, 44.1 kHz, 16-bit PCM) and `analysis.json`. `storage/` is git-ignored and must stay that way.
- Error copy, verbatim from spec §10: `Couldn't read this audio file. Try WAV or MP3.`
- Never put real music in the repo or in tests: every test sound is generated in code.
- Windows first: pass command arguments as lists (never one shell string) so paths with spaces work; the venv Python is `venvPythonPath()` from `src/lib/python.ts`.
- Every task ends with `npm run check` passing, then a commit. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Quiet passages and near-silent bands** (long intros, fade-outs, songs with no treble): faint noise must not light bands up. Pinned in Task 2 (`test_faint_noise_stays_dark`).
2. **A file that isn't usable audio** (corrupt, renamed text file, video with no sound): a clear message, a non-zero exit, nothing cached. Pinned in Task 3 (`test_cli_garbage_file_exits_2`) and Task 4 (`unreadable source`).
3. **Windows paths with spaces and accents** (`C:\Users\…\My Sóng.wav`): must analyze normally. Pinned in Task 3 (`test_cli_resamples_48k_stereo_with_spaced_unicode_path`).
4. **A stale or broken cache** (older `version`, `analysis.json` cut short by a crash): re-analyze, never crash, never reuse it. Pinned in Task 4 (`stale version` and `corrupt analysis.json`).
5. **Album-length songs (60 min)**: no running out of memory, reasonable time. FFT is done in chunks (Task 1); measured in Task 5 step 4.

- Produces (in `analyzer/features.py`):
  - constants `SR = 44100`, `FPS = 30`, `HOP = SR // FPS` (1470), `FFT_SIZE = 4096`, `N_BANDS = 32`
  - `band_levels_db(y: np.ndarray, sr: int = SR, fps: int = FPS) -> tuple[np.ndarray, np.ndarray]`: returns `(db, rms_db)`. `db` has shape `(n, 32)`, `rms_db` has shape `(n,)`, where `n = len(y) // (sr // fps)`.
  - `apply_floor(db: np.ndarray, range_db: float = 60.0) -> np.ndarray`
  - `scale_to_unit(x: np.ndarray, lo_pct: float, hi_pct: float, min_range: float = 12.0) -> np.ndarray`: works per column, output clipped to 0..1.
  - `smooth(x: np.ndarray, attack: float, release: float) -> np.ndarray`
- Produces (in `analyzer/tests/sounds.py`), all returning float32 mono at 44.1 kHz:
  - `tone(freq, seconds, amp=0.5)`
  - `gated_tone(freq, seconds, amp=0.5)`: on for the first half of every second, with **50 ms raised-cosine fades**. Hard on/off edges splash energy into every band, so fades are required.
  - `kick_bursts(times, seconds)`: at each time, `0.9·sin(2π·60·t)·exp(−t/0.05)` for 0.15 s.
  - `silence(seconds)`
  - `write_wav(path, samples, sr=44100, channels=1)`: 16-bit PCM via the stdlib `wave` module; for `channels=2` it duplicates the mono signal.

- [ ] **Step 3: Implement `analyzer/features.py`**

`band_levels_db`:
- Pad `y` with `FFT_SIZE // 2` zeros at each end, so frame `i`'s window is centred on sample `i * HOP` (time `i / FPS`).
- Take the windows with `np.lib.stride_tricks.sliding_window_view(padded, FFT_SIZE)[::HOP][:n]`. Process them in chunks of 512 frames so a 60-minute song never holds every spectrum at once.
- For each chunk: `power = |rfft(window * hann)|²`. Band power is `power @ M`, where `M` is a `(2049, 32)` averaging matrix. Each column holds `1/count` over the FFT bins in `[edges[b], edges[b+1])`. A band with no bins uses the single bin nearest its centre, as in the prototype.
- `db = 10·log10(band_power + 1e-12)`.
- `rms_db` is `20·log10(rms + 1e-9)` over the `HOP` samples centred on the frame.

`apply_floor` clamps to `percentile(db, 99.5) − range_db`.

`scale_to_unit` gets `lo` and `hi` per column with `np.percentile`, then sets `hi = max(hi, lo + min_range)`.

`smooth` is the prototype's attack/release loop.

**Interfaces:**
- Consumes: everything Task 1 produces.
- Produces:
  - `features.onsets(levels: np.ndarray, fps: int = FPS) -> tuple[np.ndarray, list[tuple[float, float]], np.ndarray]`: returns `(flux, hits, kick)`.
    - `levels` are the scaled, unsmoothed bands.
    - `flux` is all-band positive flux divided by its 99th percentile (with a 1e-6 floor), clipped 0..1.
    - `hits` is a list of `(time_s, strength)`, peak-picked from the lowest-8-band flux using the prototype's rule (Global Constraints).
    - `kick[i] = last_strength · exp(−(t − last_hit_t) / 0.22)`.
  - In `analyzer/analyze.py`: `ANALYSIS_VERSION = 1`, `MIN_SECONDS = 1.0`, `class TooShortError(ValueError)`, and `analyze_samples(y: np.ndarray, sr: int = SR) -> dict`. The dict uses exactly the spec §7 shape.
    - `duration = round(len(y) / sr, 3)`.
    - `b` = bands: floor, then scale 20/97, then smooth 0.55/0.12.
    - `l` = loudness: scale `rms_db` 15/98, then smooth 0.5/0.1.
    - `k` = kick; `f` = flux.
    - `hits = [[t, strength], …]`.
    - Rounding: convert to float64 **before** `np.round(…, 3).tolist()`. float32 values would serialize as `0.12300000339…`.
    - Raises `TooShortError("Song is too short: it needs to be at least 1 second long.")` when `len(y) / sr < MIN_SECONDS`.

def on_frames(result):  # frames well inside the "on" half of each gated second
    return [i for i in range(len(result["frames"])) if 0.1 < (i / 30) % 1.0 < 0.4]

def test_60hz_tone_lights_the_lowest_bands_only():
    r = analyze_samples(gated_tone(60, 4.0))
    assert np.mean([r["frames"][i]["b"][3] for i in on_frames(r)]) >= 0.9
    assert max(f["b"][b] for f in r["frames"] for b in range(8, 32)) <= 0.05

def test_5khz_tone_lights_its_matching_band():
    r = analyze_samples(gated_tone(5000, 4.0))
    assert np.mean([r["frames"][i]["b"][26] for i in on_frames(r)]) >= 0.9
    others = [b for b in range(32) if abs(b - 26) > 1]
    assert max(f["b"][b] for f in r["frames"] for b in others) <= 0.05

def test_faint_noise_stays_dark():
    rng = np.random.default_rng(1)
    y = gated_tone(60, 4.0) + (3e-5 * rng.standard_normal(4 * 44100)).astype(np.float32)
    r = analyze_samples(y)
    assert max(f["b"][b] for f in r["frames"] for b in range(12, 32)) <= 0.05

def test_kicks_every_half_second_become_hits():
    times = [0.5, 1.0, 1.5, 2.0, 2.5, 3.0, 3.5]
    r = analyze_samples(kick_bursts(times, 4.0))

    assert len(got) == len(times)
    for want, t in zip(times, got):
        assert abs(t - want) <= FRAME + 1e-3  # ±1 frame (the window is centred, so hits can land 1 frame early)

### Task 3: Decoding and the command line

**Files:**
- Modify: `analyzer/analyze.py`
- Create: `analyzer/tests/test_cli.py`

**Interfaces:**
- Consumes: `analyze_samples`, `TooShortError` (Task 2); `write_wav`, `gated_tone`, `tone` (Task 1's `sounds.py`).
- Produces:
  - `decode(path: str) -> np.ndarray`: runs FFmpeg with an argument list: `ffmpeg -v error -i <path> -vn -ac 1 -ar 44100 -f f32le pipe:1`. Raises `DecodeError` on a non-zero exit or zero samples.
  - `class DecodeError(Exception)`.
  - Command line: `python analyzer/analyze.py <input> --out <analysis.json>`.
    - On success: exit **0**, writes compact JSON (`separators=(",", ":")`), prints one line: `<frames> frames, <hits> hits, <seconds> s`.
    - On `DecodeError`: exit **2**, stderr `Couldn't read this audio file. Try WAV or MP3.`, followed by FFmpeg's last error line.
    - On `TooShortError`: exit **3**, with its message on stderr.
    - FFmpeg not installed (`FileNotFoundError`): exit **1**, stderr `FFmpeg not found. Run: npm run doctor`.
    - No output file is written on any failure.

  - `run-command.ts`: `type CommandResult = { code: number; stdout: string; stderr: string }`, `type RunCommand = (cmd: string, args: string[]) => Promise<CommandResult>`, and `runCommand: RunCommand`, the body moved unchanged from `scripts/doctor.ts`.
  - `analysis.ts`:
    - `ANALYSIS_VERSION = 1`
    - `type AnalysisFrame = { b: number[]; l: number; k: number; f: number }`
    - `type Analysis = { version: number; fps: number; bands: number; duration: number; frames: AnalysisFrame[]; hits: [number, number][] }`
    - `isCurrentAnalysis(value: unknown): value is Analysis`: true when it is an object with `version === ANALYSIS_VERSION`, a numeric `duration`, and array `frames` and `hits`.
    - `toAudioDataJs(a: Analysis): string`: returns `window.AUDIO_DATA=<JSON>;`.
  - `songs.ts`:
    - `songIdFor(filePath: string): Promise<string>`: lowercase hex SHA-256, computed by streaming the file.
    - `type PreparedSong = { songId: string; dir: string; wavPath: string; analysisPath: string; duration: number; cached: boolean }`
    - `class SongError extends Error { kind: "unreadable" | "too-short" | "analyzer-failed" }`
    - `prepareSong(opts: { sourcePath: string; storageRoot: string; projectRoot: string; platform: NodeJS.Platform; run: RunCommand }): Promise<PreparedSong>`
  - `prepareSong` behaviour, in order:
    1. Missing source → `SongError("unreadable", "Couldn't find this file: <path>")`.
    2. `dir = <storageRoot>/songs/<songId>`. If `song.wav` exists **and** `analysis.json` parses **and** passes `isCurrentAnalysis`, return `cached: true` with no commands run. A parse error counts as "not cached".
    3. Convert: `ffmpeg -y -v error -i <source> -vn -ac 2 -ar 44100 -c:a pcm_s16le <dir>/song.<uuid>.tmp.wav`, then rename to `song.wav`. On a non-zero exit → `SongError("unreadable", "Couldn't read this audio file. Try WAV or MP3.")`.
    4. Analyze: `<venv python> <projectRoot>/analyzer/analyze.py <dir>/song.wav --out <dir>/analysis.<uuid>.tmp.json`, then rename to `analysis.json`.
       - Exit 3 → `SongError("too-short", <stderr trimmed>)`.
       - Any other non-zero exit → `SongError("analyzer-failed", "Analysis failed: " + <last non-empty stderr line>)`.
    5. Temp files are deleted on every failure. Temp names use `crypto.randomUUID()`, so two runs never collide.
